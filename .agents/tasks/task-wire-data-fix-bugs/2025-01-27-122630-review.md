# Wire real data into features, fix React violations, build analytics tools

This change eliminates `useSyncExternalStore` misuse across 4 components (replaced with `useState` lazy initializers), replaces the 50-question `sampleQuestions` import with the full 1,283-question `loadAllQuestions()` pipeline across 5 features, and builds 6 new features: Formula Quiz with spaced-repetition-style scoring, Subject Readiness Dashboard with radar chart, Confidence Calibration Analyzer, enhanced Mistake Book with retry sessions, a Study Planner with day-by-day scheduling, and auto-seeded flashcards from incorrect answers.

Watch for: The Search Modal calls `loadAllQuestions()` on every keystroke inside `handleSearch` with no memoization (confirmed). The Insights page uses hardcoded curriculum weights that diverge from the canonical `CFA_CURRICULUM_WEIGHTS`, producing a different "Predicted Score" than the Readiness Dashboard's "Weighted Readiness" shown on the same page (confirmed). Formula quiz history grows unbounded in localStorage with no pruning (confirmed).

**Verdict**: APPROVED

## High-level view

The `useSyncExternalStore` removal is correct and complete across all 4 files. The Search Modal is the one component that calls `loadAllQuestions()` inside an event handler rather than memoizing it — wasteful but not blocking given the function's cost profile.

The Insights page now renders two independent weighted scores using different weight tables: the `ReadinessDashboard` uses `CFA_CURRICULUM_WEIGHTS` from `shared/config/subjects.ts` while the Key Metrics "Predicted Score" uses a hardcoded local object with divergent values (Equity 11% vs 13%, QM 10% vs 8%). A student seeing two different weighted scores on the same page will lose trust in the data.

The Formula Quiz engine (`formula-quiz-engine.ts`) appends every rating to `cfa-buddy-formula-quiz-history` without a cap. The weakness calculator only examines the last 10 per formula, but the full array is still parsed on every quiz start and will grow indefinitely.

The Study Plan generator is computed once via `useState` lazy initializer — the plan won't update after new practice sessions without a page reload. No manual refresh mechanism exists.

<summary>Issues (5)</summary>

1. **Search Modal calls loadAllQuestions() per keystroke** — move the call outside `handleSearch` into a `useMemo` or module-level cache so the question array is built once per mount rather than on every search input event.
2. **Revision Planner O(n*m) question lookup** — `allQuestions.find()` inside a nested loop (sessions * attempts) is O(questions * attempts). Build a `Map<id, Question>` once (like other components do) for O(1) lookups.
3. **Duplicate Set computation on every render in Mistake Book** — the "Retry" button badge shows `new Set(filteredMistakes.map(...)).size` inline in JSX, re-computing on every render rather than being memoized.
4. **Formula Quiz unbounded localStorage growth** — `cfa-buddy-formula-quiz-history` appends every rating permanently with no cap or pruning. Add a rolling cap (e.g., 1,000 most recent entries).
5. **Insights page hardcoded curriculum weights differ from shared config** — The `InsightsContent` local `weights` object doesn't match `CFA_CURRICULUM_WEIGHTS`. Import the canonical source to avoid showing two conflicting weighted scores on the same page.

## Search Modal: loadAllQuestions() called per keystroke

In `search-modal.tsx`, the `handleSearch` function calls `const allQuestions = loadAllQuestions()` every time it runs:

```tsx
const handleSearch = (q: string) => {
  if (q.length < 2) { setResults([]); return; }
  const combined: SearchResult[] = [];
  const allQuestions = loadAllQuestions(); // Called per keystroke
  ...
};
```

Every other component that uses `loadAllQuestions()` wraps the call in `useMemo(() => loadAllQuestions(), [])`. The fix is one line: move the call into a `useMemo` at component level.

## Revision Planner linear scan per attempt

In `revision-planner.tsx`, the subject-accuracy computation does:

```tsx
const q = allQuestions.find(sq => sq.id === attempt.questionId);
```

This runs for every `attempt` in every `completed` session — O(1283) per attempt. Other components in this same diff (Mistake Book, Confidence Calibration) correctly build a `Map<string, Question>` first. The Revision Planner should follow the same pattern.

## Insights predicted score uses divergent weights

`InsightsContent` has a hardcoded weights object:

```tsx
const weights: Record<string, number> = {
  'Ethical and Professional Standards': 15,
  'Quantitative Methods': 10, 'Economics': 10,
  'Financial Statement Analysis': 13, 'Corporate Issuers': 8,
  'Equity Investments': 11, 'Fixed Income': 11,
  'Derivatives': 6, 'Alternative Investments': 6,
  'Portfolio Management': 10,
};
```

`CFA_CURRICULUM_WEIGHTS` in `shared/config/subjects.ts` uses:
- Ethics: 0.15, QM: 0.08, Econ: 0.08, FSA: 0.13, CI: 0.08, EI: 0.13, FI: 0.13, Der: 0.06, AI: 0.06, PM: 0.10

Equity is 11 vs 13%, QM is 10 vs 8%, Fixed Income is 11 vs 13%. The "Predicted Score" in Key Metrics and the "Weighted Readiness" from ReadinessDashboard — both visible on the same Insights page — will show different numbers for the same underlying data. Import `CFA_CURRICULUM_WEIGHTS` and multiply by 100.

## Formula Quiz localStorage growth

`saveFormulaQuizResult` appends to `cfa-buddy-formula-quiz-history` indefinitely. With 132 formulas and regular daily practice, this grows by ~5,200 entries/year. The `getFormulaWeakness` function only examines the last 10 attempts per formula but still parses the entire history array on every quiz start. A rolling cap (keep last 1,000 entries, prune on save) prevents unbounded growth.

## Study Plan lacks refresh mechanism

`StudyPlanContent` computes its plan in a `useState` lazy initializer:

```tsx
const [plan] = useState<StudyPlan>(() => generateStudyPlan(70));
```

The plan is frozen at mount time. After completing new practice sessions, navigating back to Study Plan (SPA navigation, same mount) shows stale data. A "Regenerate Plan" button or re-computation on focus would close this gap.

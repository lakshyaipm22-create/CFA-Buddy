# Analytics and study intelligence layer for CFA Buddy

This change adds five interconnected analysis features to the question-bank system: error classification with confidence calibration, time analysis with difficulty progression tracking, spaced repetition for weak questions, progress timeline with target comparison, and a smart session recommendation engine. The approach builds a utility-first architecture where each feature has a pure-function utilities module, a React component layer consuming localStorage via `useState` lazy initializers, and dedicated test coverage. The components integrate into the existing attempt-dashboard (via tabbed navigation) and insights page.

Watch for: gap analysis uses the subject-level curriculum weight rather than per-module weights, producing identical priority scores for all modules within a subject (confirmed). The `useMemo` in attempt-review.tsx calls `setState` during render (confirmed). Cross-feature imports from `insights` and `dashboard` into `question-bank` violate the project's architectural rule (confirmed, though pre-existing in `dashboard`).

**Verdict**: NEEDS_CHANGES

## High-level view

The spaced repetition system auto-queues incorrect questions in `saveAttempt()`, creating a tight coupling between attempt persistence and the repetition subsystem. If `addToRepetitionQueue` throws (e.g. localStorage quota exceeded), the attempt itself still saves because the call happens after `localStorage.setItem`, but callers get an unhandled exception.

The gap-analysis component has a logic bug: it looks up `CFA_CURRICULUM_WEIGHTS[latest.subjectName]` (the subject weight, e.g. 0.08 for Corporate Issuers) and assigns that same value to every module within the subject. The priority ranking degenerates into a simple gap sort, making the curriculum-weight factor irrelevant.

The attempt-review component uses `useMemo` with `setState` calls inside it as a substitute for `useEffect`. This fires state updates during render, violating the React contract and the project's explicit rule against render-phase side effects.

The insights page now imports seven symbols from `@/features/question-bank/`, and this PR adds the `SmartSessionCard` import into `dashboard-content.tsx`. The project architecture mandates no cross-feature imports. The dashboard already had pre-existing violations, but the insights violations are entirely new in this diff.

The `SmartSessionCard` is rendered on the questions page and navigates to `/questions` on click. Since the user is already there, the soft navigation doesn't remount the page, and the session config written to `sessionStorage` is never re-read.

## Gap analysis weight lookup bug

In `gap-analysis.tsx`, line 42:

```typescript
const weight = CFA_CURRICULUM_WEIGHTS[latest.subjectName] ?? 0.1;
```

`latest.subjectName` is the overarching subject (e.g. "Corporate Issuers") and it returns a single number (0.08). This same value is assigned to every `ModuleResult` in the loop. The `weightedPriority` calculation (`gap * weight`) ranks modules purely by gap size. The session-recommender correctly iterates `Object.entries(CFA_CURRICULUM_WEIGHTS)` to get per-subject weights, so the intent gap here is clear — this line should look up the module name in the weights map or use a per-module mapping. Confidence: **confirmed**.

## Render-phase setState via useMemo

In `attempt-review.tsx`:

```typescript
useMemo(() => {
  if (currentAttemptQ) {
    setEditingNote(questionNotes[currentAttemptQ.questionId] ?? '');
    setNoteExpanded(!!questionNotes[currentAttemptQ.questionId]);
  }
}, [currentAttemptQ?.questionId]);
```

This calls two state setters during the render phase. The FEAT-001 findings acknowledge this as "not ideal." The correct solution is `useEffect` — it handles exactly this case (sync local state with a derived value on dependency change). Confidence: **confirmed**.

## Cross-feature import violations

The insights feature (`src/features/insights/components/insights-content.tsx`) now imports:

- `WeakTopicPanel`, `ProgressTimelineChart`, `GapAnalysis`, `TargetSetter` (components)
- `getAttempts` (utility)
- `PracticeAttempt`, `Question` (types)

All from `@/features/question-bank/`. The `topic-heatmap.tsx` already had a pre-existing violation, but the six new imports in this diff substantially deepen the coupling. These analysis components could be extracted to `src/shared/analytics/` or the insights page could be moved under the question-bank feature. Confidence: **confirmed**.

## Unhandled exception path in saveAttempt

`attempt-storage.ts` now calls `addToRepetitionQueue` in a loop after persisting the attempt:

```typescript
for (const moduleResult of attempt.moduleResults) {
  for (const qa of moduleResult.questionAttempts) {
    if (!qa.correct) {
      addToRepetitionQueue(qa.questionId, attempt.id);
    }
  }
}
```

`addToRepetitionQueue` calls `localStorage.setItem` on every invocation (via `saveQueue`). If localStorage is full, this throws `QuotaExceededError`. The attempt data was already saved successfully on the line above, but the exception propagates uncaught, potentially breaking UI flows. A try/catch around the spaced-rep loop would isolate the secondary concern. Confidence: **likely**.

## SmartSessionCard same-page navigation

`SmartSessionCard` is rendered on the questions page (`src/app/(protected)/questions/page.tsx`). When the user clicks "Start Smart Session", the handler writes config to `sessionStorage` then calls `router.push('/questions')`. Since the user is already on `/questions`, Next.js App Router treats this as a soft navigation that doesn't remount the page. The `SessionConfigurator` component would need to actively poll `sessionStorage` or listen for a custom event to pick up the new config. The card works correctly when rendered on the dashboard page. Confidence: **likely**.

## Spaced repetition dedup asymmetry

`addToRepetitionQueue` skips duplicates by `questionId`, meaning a question can only enter the queue once. If a user gets the same question wrong across multiple attempts, only the first failure queues it. Re-occurring failures don't reset a question that's already in the queue at a later interval — a question at the 14-day mark won't get bumped back to 1 day on a new incorrect attempt. This may not match user expectations for a "weakest questions" system.

## Test coverage gaps

Not tested: the `computeGapAnalysis` function (exported for testability but no test file exercises it), the `SmartSessionCard` same-page navigation edge case, the `saveAttempt` error-path interaction with spaced repetition, and the `useMemo` render-timing behavior.

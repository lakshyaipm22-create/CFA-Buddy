# UI/UX declutter: sidebar consolidation, dashboard progressive disclosure, page cleanup

This change reduces the navigation surface from 15 items across 4 collapsible groups to 7 items in 3 flat groups, collapses the 16-section dashboard down to a welcome bar + 4 stat cards + 1 CTA above the fold (with analytics behind a collapsible toggle), removes redundant components from the Questions page, and merges Weekly Report and LOS Tracker into an Insights tabbed view. The Learn page was migrated from hardcoded Tailwind zinc colors to CSS custom properties for theme consistency. All existing routes remain functional — items removed from nav are still accessible via direct links or cross-page references.

Watch for: CollapsibleSection uses a fixed `maxHeight: 2000px` which will produce a visible animation speed mismatch on short vs. tall content (confirmed). The Insights page tab state is not reflected in the URL, so deep-linking to `/insights` always opens the Overview tab regardless of where the user navigated from (confirmed). The Review page's RelatedActions still link to `/practice` which is no longer in the sidebar nav (confirmed).

**Verdict**: APPROVED

## High-level view

The sidebar went from an accordion of 4 groups with 15 entries to a flat list of 7 items under 3 quiet labels (Main, Review, Analytics). The `NavigationGroup` interface dropped its `icon` field since group-level icons no longer render. Mobile bottom nav kept its 5-slot structure but swapped Practice for Review.

The dashboard's primary intervention is progressive disclosure: everything below the stat cards is now gated behind a CollapsibleSection defaulting to closed. Components removed from the default render (badges, notifications, onboarding checklist, quick actions, AI study plan) still exist in the codebase; they lost their rendering site on the dashboard but nothing was deleted from the feature modules.

The Insights page absorbed Weekly Report and LOS Tracker via a render-prop TabsNav component. This converted the page from a server component to a client component, but all three content children were already `'use client'` so no serialization boundary actually moved. The standalone `/weekly-report` and `/los-tracker` routes still exist and cross-link to Insights.

All pages adopted a consistent layout shell: `max-w-5xl mx-auto space-y-8` with an `mb-8` header block. RelatedActions were pruned to 2 items per page, removing links to now-hidden routes (Formulas, Resources, Exam Plan).

<details>
<summary>Issues (3)</summary>

1. **CollapsibleSection fixed max-height** — The 2000px max-height causes a timing mismatch: short content (e.g., 200px tall) will appear to snap open in ~60ms while the CSS transition runs for 300ms. Collapse is worse — perceived delay before anything moves. Use `scrollHeight` via a ref for content-aware height, or accept the rough edge.
2. **Insights tab state not in URL** — Switching to the Weekly Report or LOS Tracker tab doesn't update the URL or history, so refreshing always resets to Overview and the browser back button doesn't navigate between tabs. Consider pushing a query param (`?tab=weekly-report`) from TabsNav.
3. **Orphaned navigation target** — The Review page's RelatedActions still link to `/practice`, which is no longer in the sidebar. Users land on a page they can't find again from the nav. Either restore Practice in the sidebar or point the link elsewhere.

## Navigation consolidation and hidden routes

Routes like `/practice`, `/formulas`, `/resources`, `/exam-plan`, and `/revision` are now unreachable from any navigation affordance — no sidebar entry, no mobile tab. They remain functional and some are linked via RelatedActions on other pages, but a user who has bookmarked them won't see them surfaced anywhere in the chrome. This is intentional per the task spec, but the Review page's RelatedActions linking to `/practice` is the one place where a hidden page is still actively promoted — creating a loop where users discover a page they can never navigate back to via the sidebar.

## Dashboard CollapsibleSection animation timing

The CollapsibleSection uses a `maxHeight` CSS transition: `0px` when closed, `2000px` when open, with 300ms ease-in-out. CSS transitions interpolate linearly between 0 and 2000px over 300ms regardless of actual content height. When content is 400px tall, the visible expansion completes in ~60ms (400/2000 * 300ms) and the remaining 240ms is "animating" invisible pixels. The collapse direction is worse — it takes the full 300ms to close, with the visual change concentrated at the very end, producing a perceived delay.

```
Expansion timeline (content = 400px):
0ms ──── 60ms: visible content appears
60ms ─── 300ms: transition still running, nothing visible happening
```

The opacity transition compounds the issue: it runs 0→1 over the same 300ms, so content fades in linearly while the height jumps in early. These two transitions would benefit from being decoupled or the opacity removed.

A ref-based approach using `scrollHeight` would solve this. Not blocking for a study app, but noticeable on the dashboard where the collapsed section contains charts that may be 600-800px tall.

## Insights tab state and remount behavior

The TabsNav component uses conditional rendering (`&&`), so inactive tabs unmount completely and remount on each switch. For the Weekly Report and LOS Tracker, which read from localStorage and compute statistics, this means re-parsing on every tab switch. Performance is fine for the current data volume, but if these tabs grow heavier, the unmount/remount cost will grow with them.

The tab state lives entirely in `useState` with no URL synchronization. A user navigating from `/los-tracker`'s "Also available in Insights" link lands on `/insights` showing the Overview tab, not the LOS Tracker tab they expected. Adding `?tab=los-tracker` support to TabsNav and having the cross-links use it would close this UX gap.

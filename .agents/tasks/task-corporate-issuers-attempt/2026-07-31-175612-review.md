# Corporate Issuers practice attempt system with dashboard and review mode

This change adds a complete practice attempt tracking subsystem to CFA Buddy: 158 Corporate Issuers questions stored as structured data, a localStorage-backed CRUD layer for attempt results, a seed function that recreates the user's actual CFA portal scores (120/158, 76%), and a suite of client components — attempt dashboard with circular progress rings, question review mode with bookmark toggle, retake comparison with recharts bar charts, and dashboard integration showing the latest attempt at a glance. It also fixes a Critical React Rule violation by replacing `useSyncExternalStore` with a `useState` lazy initializer in the sessions hook.

Watch for: Bookmark mutations silently replace the full attempts array in localStorage on every toggle click, with no debouncing or batching — rapid toggling under large localStorage payloads could cause noticeable jank (confirmed). The seed function fires unconditionally on every dashboard mount and on the attempts page mount and on the questions page mount (three independent `useEffect` calls), each deserializing the full attempts array to check for duplicates (confirmed). The `useLocalStorageSessions` fix removes cross-tab reactivity that the old `useSyncExternalStore` + `storage` event listener provided — sessions modified in another tab no longer propagate (confirmed).

**Verdict**: APPROVED

## High-level view

The storage layer is a thin localStorage wrapper (`attempt-storage.ts`) with a separate key from existing sessions. The seed function uses a deterministic PRNG (LCG with seed 42) to distribute correct/incorrect answers across modules with the exact score breakdown requested, then checks for an existing `ci-attempt-1` record before writing — idempotent but not free, since `getAttempts` parses the full blob each time.

The dashboard integration calls `seedCorporateIssuersAttempt()` inside a `useEffect` on the main dashboard, the attempts list page, and the questions page. Each call guards against duplicate writes, but the parse-check-deserialize cost triples. This is not functionally broken with a single seeded attempt, but the pattern sets up a scaling concern as more subjects are added.

The review component holds the full attempt in `useState` and mutates bookmarks by spreading the attempt, toggling the `bookmarkedIds` array, calling `saveAttempt` (full-array JSON.stringify + setItem), and re-setting local state. The `saveAttempt` upsert re-parses the full localStorage blob, searches by ID, replaces in-place, and re-serializes — each bookmark toggle pays this full round-trip.

The `useLocalStorageSessions` refactor correctly eliminates `useSyncExternalStore` per project rules but removes the cross-tab `storage` event listener. Sessions are now read once on mount and never update reactively.

## Seed triple invocation

Three independent `useEffect` hooks call `seedCorporateIssuersAttempt()`:

```ts
// dashboard-content.tsx
useEffect(() => {
  seedCorporateIssuersAttempt();
  const latest = getLatestAttempt('Corporate Issuers');
  setLatestAttempt(latest);
}, []);

// attempts-list-client.tsx
useEffect(() => {
  seedCorporateIssuersAttempt();
  setSeeded(true);
}, []);

// recent-attempts-section.tsx
useEffect(() => {
  seedCorporateIssuersAttempt();
  const all = getAttempts('Corporate Issuers');
  ...
}, []);
```

Each call enters `getAttempts('Corporate Issuers')` which does `JSON.parse(localStorage.getItem('cfa-buddy-attempts'))` and filters. With a single 158-question attempt the payload is ~60KB of JSON parsed three times per page transition. The duplicate check prevents double-writes, but the parse cost is unnecessary for routes where the seed already exists after the first mount.

## Bookmark persistence model

`toggleBookmark` in `attempt-review.tsx`:

```ts
const toggleBookmark = useCallback(() => {
  if (!attempt || !currentAttemptQ) return;
  const qid = currentAttemptQ.questionId;
  const updated = { ...attempt };
  if (updated.bookmarkedIds.includes(qid)) {
    updated.bookmarkedIds = updated.bookmarkedIds.filter(id => id !== qid);
  } else {
    updated.bookmarkedIds = [...updated.bookmarkedIds, qid];
  }
  saveAttempt(updated);
  setAttempt(updated);
}, [attempt, currentAttemptQ]);
```

`saveAttempt` then:
1. Reads and parses the full `cfa-buddy-attempts` JSON blob
2. Finds the attempt by ID via `.findIndex`
3. Replaces it in the array
4. Stringifies the whole array back to localStorage

A single bookmark click against a 158-question attempt (with all module results and per-question metadata) does a full serialize-deserialize cycle. Once multiple subjects exist the blob grows linearly and the cost compounds on every toggle.

## Dashboard quick-action slot replacement

The dashboard previously had a "Browse Resources" quick action pointing to `/resources`. This was replaced with "Corporate Issuers" pointing to `/questions/attempts`. The `FolderOpen` icon import was removed and `Target` used instead. If `/resources` is still a live route referenced in the sidebar or elsewhere, users lose a discovery path from the dashboard grid.

## Cross-tab reactivity removal

The old `useLocalStorageSessions` subscribed to the `storage` event:

```ts
function subscribe(callback: () => void): () => void {
  window.addEventListener('storage', callback);
  return () => window.removeEventListener('storage', callback);
}
```

The `storage` event fires when another tab modifies the same origin's localStorage. The replacement `useState(() => ...)` reads once and is inert — a behavioral delta that removes cross-tab propagation of session state.

## Test coverage gaps

Not tested: the React components themselves (no render tests for `attempt-dashboard`, `attempt-review`, `attempts-list-client`, `retake-comparison`, or `recent-attempts-section`). Filter logic in the review component (switching between all/incorrect/bookmarked) has no component-level test. The bookmark toggle path — particularly the re-render cycle after `setAttempt` — has no test coverage. This is consistent with the project's current test strategy (unit-test utilities, not components) but means UI regressions would only be caught manually.

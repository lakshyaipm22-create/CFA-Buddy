# UX architecture overhaul: grouped navigation, notifications, cross-linking, command palette, subject study hub (v2)

Five features restructure CFA Buddy's navigation and user flow into a cohesive system: collapsible grouped sidebar, mobile bottom nav, breadcrumbs, notification dropdown, command palette with quick actions and recently-visited pages, cross-page contextual RelatedActions on every practice page, and a per-subject study hub. All six issues from the v1 review have been addressed — localStorage keys corrected, dead `/settings` links changed to `/profile`, the cross-feature `useLocalStorageSessions` import moved to `src/shared/hooks/`, the stale closure in the search modal fixed with `emptyStateItemsRef`, and 27 new tests added across 4 test files.

Watch for: the **notification dropdown still imports directly from `@/features/flashcards/` and `@/features/review-queue/`** (confirmed) — the v1 fix addressed only the sessions hook, not the remaining cross-feature imports. The **page-tracking hook's `PATH_TITLES` map includes `/settings`** which doesn't exist (confirmed) — dead code that adds confusion. A **`Suspense` boundary is missing around `useSearchParams()` in the questions page** (confirmed), which will trigger a console warning in Next.js 14+.

**Verdict**: APPROVED

## High-level view

The v1 review's six issues are all resolved. The cross-feature import fix was scoped to the one hook flagged; the notification dropdown retains other cross-feature imports (`getFlashcards`, `getCardsDueToday`, `getReviewQueueSummary`), but this matches the pre-existing pattern where `src/shared/` already imports from features (header imports from gamification, analytics barrel re-exports from question-bank).

Two low-severity residual issues remain (dead `/settings` entry in PATH_TITLES, missing Suspense for `useSearchParams`), neither of which blocks shipping.

## Notification dropdown: remaining cross-feature imports

The v1 fix extracted `useLocalStorageSessions` to `src/shared/hooks/`. The component still imports:

```typescript
import { getFlashcards } from '@/features/flashcards/utils/storage';
import { getCardsDueToday } from '@/features/flashcards/utils/sm2';
import { getReviewQueueSummary } from '@/features/review-queue/utils/queue-builder';
```

Lower severity than the v1 finding because the codebase has an established precedent: the header imports from `@/features/gamification/`, `src/shared/analytics/` re-exports from `@/features/question-bank/`, and `src/shared/annotations/` re-exports from `@/features/practice/`. The project's architectural rule about no cross-feature imports appears to mean "features shouldn't import from other features," with shared acting as a glue layer that reaches into features. Acceptable for shipping; documenting the convention would prevent future confusion.

## Page-tracking PATH_TITLES stale route references

`src/shared/hooks/use-page-tracking.ts` defines:

```typescript
const PATH_TITLES: Record<string, string> = {
  ...
  '/settings': 'Settings',
  '/notes': 'Notes',
  '/study-plan': 'Study Plan',
};
```

`/settings`, `/notes`, and `/study-plan` don't have corresponding route files. These entries are dead code since the router would 404 before the page tracker records. The `/profile` route resolves via the fallback capitalizer to "Profile" — correct but accidental. The map should match actual routes.

## useSearchParams without Suspense boundary

`src/app/(protected)/questions/page.tsx` uses `useSearchParams()` at the component root:

```typescript
export default function QuestionsPage() {
  const searchParams = useSearchParams();
  const subjectParam = searchParams.get('subject') || undefined;
  ...
}
```

Next.js 14+ requires components using `useSearchParams` to be wrapped in a `<Suspense>` boundary during static rendering. Since this is a `'use client'` page component with dynamic params, functional impact is minimal, but the console warning is noisy and static optimization is degraded.

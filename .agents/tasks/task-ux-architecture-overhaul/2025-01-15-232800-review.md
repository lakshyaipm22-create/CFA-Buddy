# UX architecture overhaul: grouped navigation, notifications, cross-linking, command palette, subject study hub

Five features restructure CFA Buddy's navigation and user flow. The flat 14-item sidebar becomes four collapsible groups (Progress, Study, Practice, Planning), a mobile bottom nav appears below `md` breakpoint, breadcrumbs surface on nested routes, a notification dropdown aggregates due items, the command palette gains quick actions and recently-visited pages, cross-page contextual links eliminate dead-ends, and a per-subject study hub consolidates all study activity into one view. The implementation correctly uses `useState(() => ...)` lazy initializers for all localStorage reads and keeps new shared code in `src/shared/`.

Watch for: the onboarding checklist has **two wrong localStorage keys** (confirmed) and **two dead links** to a `/settings` route that doesn't exist (confirmed — should be `/profile`). The notification dropdown imports a hook from `src/features/dashboard/`, which is a cross-feature import into a shared component — violating the project's architectural rule (confirmed).

**Verdict**: NEEDS_CHANGES

---

## High-level view

The navigation restructuring is driven by a single `navigationGroups` config that feeds the sidebar, mobile bottom nav, and breadcrumbs, so adding or reordering pages requires only a config change. Collapsed state persists in localStorage, and the active group auto-expands by checking `pathname.startsWith(item.href)`.

The notification dropdown imports `useLocalStorageSessions` from `src/features/dashboard/hooks/` — a cross-feature import into a shared component that violates the project's architectural boundary. The fix is to move the hook to `src/shared/hooks/` or inline the localStorage read.

Cross-page linking via `RelatedActions` is applied consistently to 7 pages with a responsive grid pattern. The command palette adds a two-zone keyboard navigation model: quick actions + recent pages when empty, search results when typing.

The subject study hub aggregates per-subject progress, weak areas, and recent sessions from localStorage on every mount. Acceptable at current scale.

The onboarding checklist contains three confirmed bugs that prevent auto-completion of items and produce 404 navigation.

## Onboarding checklist: three confirmed data-binding bugs

The checklist at `src/shared/components/ui/onboarding-checklist.tsx` defines storage keys at the top of the file:

```typescript
const SESSIONS_KEY = 'cfa-practice-sessions';  // WRONG: should be 'cfa-buddy-sessions'
const FLASHCARDS_KEY = 'cfa-flashcards';        // WRONG: should be 'cfa-buddy-flashcards'
```

Every other file in the codebase (`session-storage.ts`, `use-local-storage-sessions.ts`, `question-selector.ts`, `flashcards/utils/storage.ts`) uses `'cfa-buddy-sessions'` and `'cfa-buddy-flashcards'`. With these keys wrong, two of the five checklist items can never auto-complete regardless of user activity — the checklist will persist on the dashboard for users who have already done sessions and created flashcards.

Additionally, items 1 and 5 link to `/settings`:
```typescript
{ href: '/settings', ... }  // No route exists — should be '/profile'
```
The sidebar correctly links to `/profile`, and `src/app/(protected)/profile/page.tsx` exists. Clicking these checklist items navigates to a 404.

## Cross-feature import violating architectural boundary

`src/shared/components/layout/notification-dropdown.tsx` imports:
```typescript
import { useLocalStorageSessions } from '@/features/dashboard/hooks/use-local-storage-sessions';
```

The project rule states no cross-feature imports — shared components must not import from feature directories. The hook itself is trivial (a `useState` lazy initializer reading `'cfa-buddy-sessions'`). Move it to `src/shared/hooks/use-sessions.ts` or inline the localStorage read directly in the notification component.

## Command palette keyboard navigation edge case

The `emptyStateItems` array and `totalEmptyItems` count are computed at render time:
```typescript
const emptyStateItems = [...QUICK_ACTIONS.map(a => a.href), ...recentPages.map(p => p.path)];
const totalEmptyItems = emptyStateItems.length;
```

`recentPages` is initialized from localStorage when the modal opens, so in practice the array doesn't change mid-session. But `handleKeyDown` is not wrapped in `useCallback` with the correct deps — if someone later makes `recentPages` reactive, the bounds-checking in keyboard navigation will use stale values. Latent fragility, not a current bug.

## Test coverage gap

The five features introduce ~2800 lines of new UI code with no new unit tests. The new components (notification dropdown, onboarding checklist, subject study hub, breadcrumbs, page tracking) have no dedicated test coverage. The localStorage key bugs in the onboarding checklist would have been caught by asserting `checkSessionsExist()` returns true after writing to `'cfa-buddy-sessions'`.

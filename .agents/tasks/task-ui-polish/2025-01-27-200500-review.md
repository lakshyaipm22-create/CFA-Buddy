# Design system enforcement across page layouts and color tokens

This change normalizes page-level layout wrappers, replaces hardcoded Tailwind color classes and non-existent CSS variables with the project's actual design tokens, removes a redundant FlashcardStats display, and re-styles the mock exam CTA to use the Gold brand color. The approach is mechanical: sweep each page/component, apply the canonical pattern (`mx-auto max-w-5xl space-y-8`, inline styles referencing `var(--foreground)` / `var(--card-border)` / etc.), and delete the dead code paths. Watch for: the dashboard still uses `max-w-4xl` while every other page was moved to `max-w-5xl` (confirmed); gamification and spaced-repetition components were explicitly left out of scope but still reference non-existent CSS variables that will render as `unset`/transparent at runtime (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

The page wrapper standardization touches ten route files and is consistent — all converge on `mx-auto max-w-5xl space-y-8` — except the dashboard, which retains `max-w-4xl`. Whether this is intentional (the dashboard layout is denser) or an oversight determines whether it needs a follow-up.

The CSS variable migration replaces two classes of problematic references: Tailwind dark-mode utility classes (`bg-zinc-900`, `text-white`, `border-zinc-800`) and invented variable names (`--text-primary`, `--text-muted`, `--border-primary`) that were never defined in `globals.css`. The replacement uses inline `style` props pointing at the real tokens, which trades Tailwind composability (hover states, responsive modifiers) for guaranteed correctness.

The FlashcardStats removal is clean: the deck component already renders its own stats grid, so the page-level import was pure duplication. The mock exam CTA switches from Navy to Gold, matching the primary action pattern seen on the dashboard.

## Dashboard max-width gap

Every page touched in FEAT-001 converges on `max-w-5xl`. The dashboard content component at `src/features/dashboard/components/dashboard-content.tsx:213` still renders inside `max-w-4xl`. This creates a visible jump when navigating between pages: the content area narrows by ~128px on the dashboard. The stated acceptance criteria for FEAT-001 is "All page wrappers use `mx-auto max-w-5xl space-y-8`", so this is either an oversight or an undocumented exception.

## Non-existent CSS variable debt

The FEAT-002 findings acknowledge that `badges-display.tsx`, `streak-display.tsx`, `weekly-goal.tsx`, `review-complete.tsx`, and `review-session.tsx` still use `var(--border-primary)`, `var(--text-primary)`, `var(--text-muted)`, `var(--text-secondary)`, and `var(--background-secondary)`. None of these are defined in `globals.css`. The browser resolves an undefined custom property to its guaranteed-invalid value:

- `border-color: var(--border-primary)` → no visible border
- `color: var(--text-primary)` → unset, inherits from parent (fragile)
- `background: var(--background-secondary)` → transparent, losing the card container effect

These components are visible to users (gamification appears on the dashboard, spaced-repetition is a standalone feature). The polish pass leaves known-broken rendering in production paths.

## Tabs hover state gap

The `tabs-nav.tsx` component no longer has a hover color transition for inactive tabs. The replacement inline style sets a static color:

```tsx
style={{
  color: activeTab === tab.id ? '#C5A258' : 'var(--foreground-secondary)',
}}
```

Since inline styles can't express `:hover`, inactive tabs lack any hover feedback. Users get no visual confirmation that a tab is interactive until they click it. A CSS class or `onMouseEnter`/`onMouseLeave` state would restore it.

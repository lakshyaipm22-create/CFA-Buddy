# Analytics dashboard for CFA Buddy test sessions (v2)

A comprehensive analytics feature adding a computation engine, test history dashboard at `/analytics`, individual session deep-dive at `/analytics/session/[sessionId]`, trend visualizations, auto-generated insights, and session comparison mode — all sourced from localStorage with Recharts lazy-loaded throughout. 5,271 new lines across 28 files with 59 unit tests covering the computation layer.

All five issues from the v1 review have been addressed: ComparisonCard `goodDirection` ternary now correctly distinguishes up vs down directions; the confidence breakdown bar uses a `certain` total field that partitions with `thinkSo` and `guess` to sum to 100%; session comparison now iterates per-attempt with question-bank lookups for mixed-mode subject data; `loadAllQuestions()` has module-level caching keyed on the raw localStorage string; and the `suffix` prop is rendered in the diff display.

**Watch for:** Confidence calibration in `trend-engine.ts` uses a different formula (mastered + knowledgeGap / total) than `trend-charts.tsx` (certainCorrect / certainTotal), meaning the trend engine function goes unused while the chart has its own inline computation (likely). The `handleExportCSV` callback revokes the blob URL synchronously after `link.click()`, which is technically premature per spec though browsers handle it in practice (possible).

**Verdict**: APPROVED

## High-level view

The computation layer separates raw `QuestionSession` processing from presentation. `computeSessionStats` produces typed `AnalyticsSession` records with pre-computed confidence breakdowns and matrices; filters and sorts operate on these derived records. The module-level caching in `question-loader.ts` prevents repeated JSON parsing across page navigations while correctly invalidating via `saveImportedQuestions`.

The session comparison component now resolves per-question subjects from the question bank rather than relying on session-level metadata, which means mixed-mode sessions produce meaningful subject-by-subject breakdowns. The `loadAllQuestions()` call inside the comparison's `useMemo` hits the module-level cache rather than re-parsing localStorage.

The `computeConfidenceCalibration` export in `trend-engine.ts` measures overall "confidence-correctness alignment" (mastered + knowledgeGap) while the chart component inline-computes classic calibration (certain-correct / certain-total). The exported function is dead code in this diff — if later consumed expecting the chart's semantics, it will produce different numbers.

## Calibration formula divergence

`trend-engine.ts` defines `computeConfidenceCalibration` as:

```typescript
calibrated += s.confidenceMatrix.mastered + s.confidenceMatrix.knowledgeGap;
// divided by total questions
```

This measures "how often confidence level matched correctness" (both certain+correct and guess+wrong). The chart component in `trend-charts.tsx` instead computes:

```typescript
certainCorrect += s.confidenceMatrix.mastered;
certainTotal += s.confidenceMatrix.mastered + s.confidenceMatrix.misconception;
calibration = certainCorrect / certainTotal;
```

This measures "of the times you said Certain, how often were you right?" — classic confidence calibration. The `trend-engine.ts` export is not imported by any component in this diff, making it dead code with a misleading name. The function *is* tested in `trend-engine.test.ts`, so changing the formula would require test updates.

## Test coverage gaps

Not tested: UI component rendering, lazy-loading Recharts wrapper behavior, CSV export output format, and clipboard share functionality. The 59 unit tests thoroughly cover the computation layer but no integration tests verify the rendered output.
